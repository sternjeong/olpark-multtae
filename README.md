# 올팍 물때 — 올림픽공원 밀물·썰물 시간표

> **기관 공식 서비스가 아닙니다.** 이 서비스는 「2026년도 한국체육산업개발(주) 공공데이터 활용 경진대회」 출품을 위해 개인이 만든 서비스이며, 한국체육산업개발(주)이 운영하거나 보증하지 않습니다.

- 서비스: https://sternjeong.github.io/olpark-multtae/
- 오늘 올림픽공원은 몇 시에 차오르고(만조) 몇 시에 빠지며(한산한 창), 그 물결은 무엇이 만드는가(강좌 시작·대형 공연·짧은 승하차)를 기관 개방 데이터로 보여 주는 정적 웹 서비스입니다.
- 서버·DB·로그인·유료 API·외부 라이브러리 없음. 빌드는 Python 3.12 표준 라이브러리만 씁니다.

## 빌드와 실행
```bash
python3 -m build.main --out site/data --offline     # 스냅숏만으로 빌드(네트워크 불필요)
python3 -m unittest discover -s tests               # 테스트
python3 -m http.server 8000 --directory site        # http://localhost:8000/ 에서 확인
```
- `--offline`을 빼면 먼저 포털에서 원천을 다시 받습니다(`build/fetch.py`, 실패하면 스냅숏 사용).
- `--archive archive/live`: 실시간 기록 CSV 폴더(archive 브랜치)를 읽어 `live.json`을 만듭니다.
- 실시간 1회 수집: `python3 -m build.live collect --archive archive/live`
- 개방 데이터 점검 하나만 다시 계산: `python3 -m build.quality --check Q01`

## 자동화(GitHub Actions)
| 워크플로 | 주기 | 하는 일 |
|---|---|---|
| `build-deploy.yml` | main 푸시 · 매시 7분 · 수동 | 빌드 → 테스트 → GitHub Pages 배포 |
| `collect-live.yml` | 15분마다 | 실시간 주차 값을 `archive` 브랜치 `live/parking_YYYY-MM.csv`에 기록(브랜치가 없으면 만듦) |
| `refresh-sources.yml` | 매주 월 03:00 KST | 원천 재다운로드 → 바뀌었고 테스트 통과면 PR, 실패면 이슈 |
| `keepalive.yml` | 매월 1일 | 60일 무활동으로 예약 실행이 꺼지지 않게 기록 |
| `ci.yml` | PR | 오프라인 빌드 + 테스트 |

저장소 설정: **Settings → Pages → Source = GitHub Actions**, **Settings → Actions → General → Workflow permissions = Read and write**(collect-live·keepalive·refresh가 커밋·PR·이슈를 만듭니다. PR 생성에는 "Allow GitHub Actions to create and approve pull requests"도 켭니다).

## 선택 키 연결(Actions secret)
키가 없어도 모든 기능이 동작합니다. 키를 넣으면 다음이 켜집니다. **Settings → Secrets and variables → Actions → New repository secret**:

| 이름 | 발급처 | 연결되면 |
|---|---|---|
| `DATA_GO_KR_KEY` | 공공데이터포털 일반 인증키(디코딩 키) | 파일데이터 자동변환 API(odcloud)로 원천 갱신, 특일정보 API로 공휴일 확인, 기상청 단기예보 "비 예보" 칩(활용신청: 15084084, 15012690) |
| `CULTURE_API_KEY` | 문화공공데이터광장 | 공연 자동 목록·2025 연계 데이터 검증. 엔드포인트를 이 환경에서 확인하지 못해 `build/static/kcisa_endpoints.json`을 사람이 채워야 켜집니다 |

키 값은 로그·산출물에 남기지 않으며(테스트로 확인) 화면에는 연결 여부만 표시합니다.

## 계산 방법 요약
자세한 식과 현재 값은 서비스의 `#/method` 화면에 있습니다.
1. **점유 재구성**: 입출차 21만여 건으로 분 단위 주차 대수 O(m) = Σ 1[입차 ≤ m < 출차]. 7/1은 그 전 입차 차량이 없어 점유 통계에서 제외.
2. **요일군 프로파일**: 평일·토·일(공휴일은 일요일로 가정)별 10분 입차 평균, 점유 중앙값, 관측 범위(평일 25~75%, 주말 최소~최대·3구간 평활). 행사 의심일 제외.
3. **계절 지수**: 월별주차현황 2023~2025 평균의 7월 대비 비율. 날짜별 예보 = 지수 × 프로파일(하루 모양은 7월과 같다고 가정, 모든 화면에 근거 꼬리표).
4. **행사일(사리)**: 14~19시 입차 후 150분 이상 머문 차가 같은 요일군 중앙값의 1.5배 이상인 날. Δ = 행사일 − 보통날을 공연 시작 시각에 맞춰 옮겨 더함(계절 지수 미적용). 기준 시작 시각은 공연 포스터 데이터에서.
5. **강좌 계수 β**: 평일 요일별 입차 편차를 강좌 시작 수요(정원/3을 시작 전 30분에 배분) 편차로 원점 통과 회귀. 새벽 독립 검증(계산 vs 실제) 공개.
6. **만조·한산한 창**: 3구간 평활 곡선의 돌출 봉우리(그날 최대의 10% 이상, 90분 간격), 점유 ≤ 60%·입차 ≤ 중앙값이 30분 이상 이어지는 구간.
7. **검증**: 7/1~21 학습 → 7/22~31 검증, 평탄선·단일 프로파일과 비교한 10분·1시간 MAE.
8. **실시간**: 원자료와 기준이 달라 예보와 같은 축에 그리지 않고, 자체 아카이브의 같은 요일·15분 슬롯 기록과만 비교.

## 구조
```
site/      정적 루트(Pages 배포 대상). index.html, 404.html, assets/, data/(빌드 산출)
build/     빌드 파이프라인(표준 라이브러리), schemas/(JSON Schema), static/(공휴일·제안·포털 목록 등)
data/raw/  원본 CSV 스냅숏(CP949)과 manifest.json
tests/     python3 -m unittest
docs/      ACCEPTANCE.md(수용 체크리스트), IMPLEMENTATION_NOTES.md(명세와 다른 점), screenshots/
```
